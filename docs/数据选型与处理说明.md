## 1. 主数据集决定

**v0.1 主数据集：天池 220316 · eCommerce behavior data from multi category store（REES46/Open CDP）。**

- 数据页：<https://tianchi.aliyun.com/dataset/220316>
- 本地文件：`2019-Oct.csv`（约 5.3GB）、`2019-Nov.csv`（约 8.4GB），共约 13.7GB
- 覆盖时间：2019-10-01 至 2019-11-30（UTC）
- 字段：`event_time, event_type, product_id, category_id, category_code, brand, price, user_id, user_session`
- 行为：`view`、`cart`、`purchase`；这两个月的数据中没有 `fav`，也没有 `remove_from_cart`
- 许可：天池页面标注 CC BY-ND 4.0；Kaggle 原页面标注数据文件版权归原作者。课程内使用并注明来源，**原始数据和用户级明细不再公开分发**。

### 为什么选它

1. **真实点击流**：浏览、加购、购买齐全，能做顺序漏斗和推荐；
2. **字段足够支撑现有页面**：价格、品牌、类目名称、会话 ID，能补上金额、品牌排行、会话分析；
3. **时间跨度 2 个月**：留存、时间切分、冷启动分析都比 9 天的淘宝 649 更稳；
4. **数据量可控**：只取 Oct + Nov，不全量处理作者整个系列；用 DuckDB 全量扫描约 3.5 分钟，按用户抽 1% 后样本约 20MB；
5. **与团队已有调研一致**：组长 2026-11-15 的调研已把该数据集列为候选，并指出"首版规模偏大"；本轮用"两个月 + 用户抽样 + DuckDB"解决了规模问题。

### 备选与不选原因

| 数据集 | 优点 | 不选/暂缓原因 |
| --- | --- | --- |
| 天池 220316（本选） | 真实点击流 + 价格 + 品牌 + 类目名 + 会话 + 2 个月 | 无年龄/性别；金额不是订单 GMV；类目名/品牌有缺失 |
| RetailRocket | 体量小、浏览/加购/交易齐全 | 无价格、无类目名（要关联属性表）、购买稀疏，RFM 的 M 和品牌排行做不了 |
| eCommerce Events History in Cosmetics Shop | 字段与 220316 相同、体量更小 | 单类目（美妆），品牌/类目多样性不如多类目店；可作为 220316 许可或规模有问题时的回退 |
| 淘宝 UserBehavior 649 | 数据经典、字段干净 | 只有 9 天、无价格/品牌/类目名，留存和金额分析太弱 |
| 京东 JData | 有年龄/性别/注册日期 | 无价格；官方下载入口不稳定；加购数据只有最后一周 |
| 早期下载的零售发票 CSV | 有性别/年龄/单价/数量 | 99,457 行对应 99,457 个客户，每人只有 1 条，无法做漏斗/留存/推荐 |

> 如果组长和团队最终决定改用其他数据集，`data_algo` 的规范字段和适配层可以调整；当前 v0.1 以 220316 为准。

## 3. 字段映射与清洗规则

### 统一字段

| 原始字段 | 统一字段 | 处理 |
| --- | --- | --- |
| `user_id` | `user_id` | 字符串，保留匿名 ID |
| `product_id` | `item_id` | 字符串，避免大整数精度问题 |
| `category_id` | `category_id` | 字符串；缺失记 `unknown` |
| `category_code` | `category_code` | 原样保留；缺失为 null |
| `brand` | `brand` | 原样保留；缺失为 null |
| `event_type` | `behavior_type` + `raw_event_type` | view→pv、cart→cart、purchase→buy；原始值保留追溯 |
| `event_time` | `event_time` | 解析为 UTC |
| `price` | `price` | float；空值保留；负价格判无效；0 单独计数 |
| `user_session` | `session_id` | 字符串；缺失为 null |

派生字段（加载时生成）：

- `event_time_cn`：北京时间（UTC+8）
- `date`：北京时间的日期
- `hour`：北京时间的小时 0–23
- `event_ts`：UTC 时间的 int64 纳秒，用于稳定排序

### 清洗规则

1. 缺 `user_id` / `item_id` / `event_time` → 无效行；
2. 时间无法解析 → 无效行；
3. 行为类型未知 → 无效行；
4. 价格为负 → 无效行；
5. 价格为空 → 保留行为，金额统计时忽略；
6. 价格为 0 → 保留，单独计数；
7. `category_id` 缺失 → `unknown`；
8. `category_code` / `brand` 缺失 → null，不编造；
9. 完全重复行 → 去重；
10. ID 一律字符串。

详细字段定义见 [数据字典](../data_algo/DATA_DICTIONARY.md)。

## 4. 抽样

- **按用户抽样**，不是按行随机截取；
- `user_id % 1000 < per_mille`，默认 `per_mille=10`，约 1% 用户；
- 被抽中的用户保留其在 Oct–Nov 的**完整历史**，避免行为链断裂；
- 固定种子 `20261116`，结果可复现；非数字 ID 用带种子的哈希；
- 抽样结果：**52,687 用户 / 1,079,354 条行为**，Parquet 约 20MB；
- `--per-mille` 可调大（20=2%、50=5%、1000=全量），用于扩大训练或做稳健性检查。

## 5. 六类统计口径

| 分析 | 口径 | 本次结果（1% 样本） |
| --- | --- | --- |
| 概览 | 事件数、去重用户/商品/类目/品牌、行为分布、购买金额 | 1,079,354 事件、52,687 用户、81,693 商品 |
| 每日/每时 | 按北京时间分组，统计各行为、用户数、购买金额 | 62 天、24 小时 |
| 顺序漏斗 | 同用户+同商品，浏览时间 < 加购时间 < 购买时间；同一时间戳不推进多个阶段 | 555,180 → 20,556（3.70%）→ 8,470（41.20%） |
| RFM | 最近购买天数 R、购买次数 F、购买金额 M；无购买 R/M 为 null | 有购买 6,976 人；高频活跃 430 人；潜在转化 45,711 人 |
| 用户画像 | 行为权重 × 时间衰减，按类目/品牌汇总 Top5；价格带；最近行为 | 每个用户一份；仓库只放方法，不放用户级明细 |
| 留存 | 样本首现 cohort，第 1–7 天活跃比例；null=未覆盖，0=无人回访 | 次日 10.92%，第 7 日 5.49% |
| 购买排行 | 过滤 buy，按类目/品牌/商品聚合；购买用户数独立去重 | 手机类目 7,456 次，占金额 68.07% |
| 购物车放弃 | 有加购、无购买的会话/用户商品对 | 59.19% |

金额口径：每条 purchase 事件按 1 件、单价汇总，**不是订单 GMV**，不能用于客单价/销售额结论。

## 6. 已知限制

1. 没有年龄、性别、城市 → 不推断人口属性，画像只做行为偏好；
2. 没有订单号、数量、优惠、运费 → 金额是行为口径，不是 GMV；
3. 没有收藏，10–11 月也没有 `remove_from_cart` → 漏斗为浏览→加购→购买，要求严格递增，同一时间戳不推进多个阶段；购物车放弃按"有加购、无购买"判断；
4. 类目名缺失 32.2%、品牌缺失 13.9% → 保留 null，不编造；类目统计按 ID；
5. 留存是"样本首现留存"，不是注册留存；
6. 原始时间是 UTC，界面/统计按北京时间；跨日会出现 12-01；
7. 数据源实际时区未知，小时峰值在 0 点不能直接当作中国用户行为结论；
8. 1% 样本用于离线开发和评测，不代表线上只服务这 1% 用户；模型可以推理全量用户，冷启动用热门兜底；
9. RFM 阈值 R≤7 天、F≥3 次是针对 2 个月数据的初始值，可配置，后续可在验证集上调整。

## 7. 产出与复现

代码与说明：

- `data_algo/`：清洗、抽样、统计代码与测试；
- `data_algo/README.md`：运行方式；
- `data_algo/DATA_DICTIONARY.md`：字段与指标定义；
- `data_algo/RESULTS_SUMMARY.md`：本轮结果摘要；
- `data_algo/reports/`：聚合结果 JSON 快照（不含原始数据和用户级画像）。

复现：

```bash
cd data_algo
.venv/Scripts/python -m pip install -r requirements.txt
.venv/Scripts/python -m pytest
.venv/Scripts/python -m data_algo.cli build-sample --engine duckdb --per-mille 10
.venv/Scripts/python -m data_algo.cli analytics
.venv/Scripts/python -m data_algo.cli export-website \
  --input ../data/processed/events_sample.parquet \
  --output ../data/exports/website_events.csv
```

原始 CSV 放 `data/raw/`（团队约定）或 `archive/`（本机独立开发）。
当前 30 个 pytest（含主分支 `backend/app/importing.py` 的 CSV/Parquet 兼容测试），
覆盖时区、重复、缺失、同时间戳漏斗、留存 null/0、RFM 缺失 R、排行、画像和网站导出。

## 8. 网站标准入库导出

主分支后端已经实现导入、数据版本、统计与推荐适配，契约见
[数据与算法交付约定](数据与算法交付约定.md)。本模块另生成一个网站入库文件：

```bash
.venv/Scripts/python -m data_algo.cli export-website \
  --input ../data/processed/events_sample.parquet \
  --output ../data/exports/website_events.csv
```

- 只含 `user_id,item_id,category_id,behavior_type,timestamp` 五列；
- timestamp 为 UTC 毫秒（13 位）；
- 行为只保留 pv/fav/cart/buy，remove_from_cart 等排除并写入导出报告；
- 未知类目为空；不编造；
- 已用主分支 `backend/app/importing.py` 对 CSV/Parquet 实际产出做兼容测试；
- 完整训练 Parquet 保留品牌、价格、会话等特征，不进入网站五列文件。
