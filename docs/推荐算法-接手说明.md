# 推荐算法接手说明

推荐模块根据用户的历史行为生成最多 10 件商品的有序列表。它提供 Python 调用和可独立启动的 HTTP 服务，结果含商品 ID、类目、排名、分数和推荐原因。

## 三个正式模型

| 模型版本 | 用什么做推荐 | 冻结 Recall@10 / NDCG@10 | 覆盖商品数 |
| --- | --- | --- | ---: |
| `popular_v1` | 按以前的购买次数排热门榜。新用户也能得到推荐 | 0.17365 / 0.10100 | 16 |
| `itemcf_v1` | 找经常被同一批用户浏览、加购或购买的商品，再按用户历史个性化推荐 | 0.14113 / 0.07908 | 5,372 |
| `bpr_mf_buy_v1` | 从购买记录学习用户与商品的向量，用内积排序 | 0.13775 / 0.07727 | 727 |

数据来自 2019 年 10–11 月的历史电商样本。以上是在 1,122 名有可达购买目标用户上的冻结离线结果。Popular 在这次测试更擅长命中后续购买，ItemCF 推荐过更多不同商品。结果适用于该次样本和评估规则，网站实际表现需上线前后另行验收。P0-REC-07 的 H1 改进幅度低于预先约定的门槛，作为研究记录保留。 [技术报告](P0-REC-06-推荐算法最终技术报告.md) · [最终研究](P0-REC-07-最后一次推荐优化实验.md)

## 手动跑起来

在仓库根目录打开 Windows PowerShell，安装 Python 3.12 后执行：

~~~powershell
py -3.12 -m venv .venv
$py = (Resolve-Path '.venv/Scripts/python.exe').Path
$env:PYTHONUTF8 = '1'
& $py -m pip install -r recommendation/requirements-http.txt
& $py -m pytest -q recommendation/tests
~~~

检出团队 GitHub 的交付分支 `feat/recommendation-final-delivery`，在 `artifacts/p0-rec-04a/release-assets/` 可以找到 `registry.json` 和三个 `.asset`。保留该目录结构即可运行，启动时无需行为数据、数据库或训练。 [四个文件的 SHA-256 与发布状态](推荐算法-AI接手指南.md#模型资产与版本)

在第一个终端启动服务。结束时按 Ctrl+C。

~~~powershell
& $py -m recommendation.http_service --host 127.0.0.1 --port 9001
~~~

打开第二个 PowerShell 终端，仍从仓库根目录运行以下命令。这里用虚构用户演示新用户兜底。

~~~powershell
$registry = 'artifacts/p0-rec-04a/release-assets/registry.json'
$model = 'itemcf_v1'
$entry = (Get-Content -Raw -Encoding UTF8 -LiteralPath $registry | ConvertFrom-Json).models.$model
$base = 'http://127.0.0.1:9001'
Invoke-RestMethod "$base/health"
Invoke-RestMethod "$base/ready"
$payload = @{
    user_id = 'course-demo-user'
    dataset_id = $entry.dataset_id
    model_version = $model
    limit = 3
} | ConvertTo-Json
Invoke-RestMethod "$base/predict" -Method Post -ContentType 'application/json' -Body $payload |
    ConvertTo-Json -Depth 5
~~~

正常时两个检查返回 `ready`，推荐请求返回 `items`。用 `rank` 作为展示顺序，`reason` 用于说明原因。模型分数的含义随模型和候选来源变化。遇到 409 检查 `dataset_id` 是否来自所选模型的注册表条目。正式网站入库后会有自己的数据版本，由接手同学核验并绑定。
