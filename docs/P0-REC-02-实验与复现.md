# P0-REC-02 ItemCF 对照实验与复现

ItemCF v1 已在真实交接样本上完成验证与一次正式测试。验证选出的配置为 `n80_recent100`。在相同的 1,122 名测试有效用户上，ItemCF 的 Recall@10 和 NDCG@10 均低于 Popular v1。ItemCF 的主覆盖率从 0.02124% 提升至 7.13157%。购买排序仍以 Popular v1 为参照。

## 基线与评估入口加固

开工时检查了分支、HEAD、工作区和索引。P0-REC-01 ZIP 的 SHA-256 与交付记录一致，ZIP 中与仓库对应的 30 个文件逐字节匹配，14 个工作文件属于已审查改动。使用 `feat/p0-rec-01` 创建单独本地基线提交 `fab15a9deec9aca9bd7731e07db1d83daa482b9b`，再创建 `feat/p0-rec-02`。Git 提交依仓库属性统一了聚合 JSON 的换行符，不影响内容。代码审查包随附工作树完整补丁。前后端、数据库和发布流程没有变更。

- `History` 构造时防御性复制可写输入，事件次数字典和已购字典成为只读映射，目录与各用户已购集合成为不可变集合。测试验证外部改动原字典及尝试写入共享映射均不能改变候选、购买过滤或评分。
- `BenchmarkStage.from_split` 绑定训练起点、拟合截止点、目标终点及完整切片行数。`evaluate` 在执行排名前校验两段范围与行数，拒绝截止不匹配、截掉一部分窗口、跨边界或历史行数不一致。生产实验只接收由原始样本统一切出的快照。
- 代码和依赖记录包含 Git 完整 SHA、分支、工作树状态、数据 SHA-256、Popular 报告指纹、模型配置、Benchmark 文档、主要依赖的实际版本，以及所有运行模块和直接上游依赖的逐文件 SHA-256。P0-REC-01 的既有实验报告仍原样保留。
- 风险修复完成后与 ItemCF 最终源码完成后各复跑一次真实 Popular。与冻结报告比较，只去掉新旧必然不同的源码指纹，其他结果字段完全相等，涵盖验证和测试各组的指标、分母、覆盖率和推荐序列指纹。详见 [基线保持与复跑证据](../recommendation/reports/p0-rec-02-verification.json)。

## 代码如何从历史生成 Top10

1. 从截止点以前取浏览 `pv`、收藏 `fav`、加购 `cart` 和购买 `buy`。同一用户商品对只记一次，得到二值矩阵 X。移出购物车、品牌和价格不参与。
2. 两件商品经常被同一批人浏览或购买时，共现数会较大。余弦将共现数除以各自用户数的几何平均，避免仅按共现总次数排序。若 Uᵢ 是与商品 i 有正反馈的用户集合，公式为 **sim(i, j) = |Uᵢ ∩ Uⱼ| ÷ √(|Uᵢ| × |Uⱼ|)**。无共现、零分、非有限值和 i 到 i 的边均不进入邻居表。
3. 以 CSR 按 256 个商品一块计算共现。保留各商品得分最高的 TopN 个邻居，同分按字符串商品 ID 升序。截断试验保留每位用户最近的 100 件不同商品，按最后一次正向行为排序，同一时刻按商品 ID 升序。相同二值矩阵同时提供邻居构造和用户种子。
4. 每位用户把其历史商品的邻居分数加总。候选仍以完整历史目录为准，按完整历史过滤该用户已买的商品。去重后按总分降序、字符串 ID 升序取前十。允许浏览过的商品从其他种子获得推荐分，但邻居表自身没有自环。
5. 冷启动、无可用邻居或不足十件时调用同一截止点的热门榜，补位时同样过滤已购并跳过已选商品。每项都记录实际来源。ItemCF 分数为余弦相似度之和，兜底分数为历史购买次数，两类分数各自用于排序。

### 三用户、五商品的手算例子

| 用户 | 二值正反馈 |
| --- | --- |
| 甲 | 购买 A，浏览 B 两次 |
| 乙 | 收藏 A，加购 C |
| 丙 | 浏览 C、D、E |

U_A = {甲,乙}，U_B = {甲}，U_C = {乙,丙}，U_D = U_E = {丙}。B 的两次浏览仍只记一次。因此 sim(A,B) = 1/√2 ≈ 0.7071，sim(A,C) = 1/2 = 0.5，sim(C,D) = sim(C,E) = 1/√2，sim(D,E) = 1，其余非对角配对为 0。

甲的种子是 A 和 B。B 因 A 获得 0.7071，C 因 A 获得 0.5。A 虽从 B 得分，仍因已购被过滤，所以甲的 Top2 是 B、C。乙的种子是 A 和 C，B、D、E 各得约 0.7071，同分顺序为 B、D、E，A 和 C 各得 0.5。乙的 Top2 是 B、D。同样的目录能产生不同用户的排序。

## 主要变更与限制

| 文件 | 用途 |
| --- | --- |
| `recommendation/benchmark.py` | 只读历史，窗口与训练截止绑定，继续共用既有宏平均 |
| `recommendation/popular.py`、`recommendation/run.py` | 将新窗口接入原热门流程，补充可追溯信息和共同评估记录 |
| `recommendation/itemcf.py` | 二值交互、分块余弦、稀疏邻居、个性化与热门补位 |
| `recommendation/itemcf_v1.json`、`recommendation/itemcf_experiment.py` | 固定参数网格、只用验证选择、冻结后测试 |
| `recommendation/tests/test_benchmark.py`、`recommendation/tests/test_itemcf.py` | 窗口与不可变性回归、人工余弦、个性化、资源上限和选择流程 |
| `recommendation/reports/p0-rec-02-*.json`、`recommendation/README.md`、本文 | 真实结果、验证数据与证据入口 |

全量 ItemCF 和截断 ItemCF 均在验证中落后于热门。真实数据的历史商品中位数只有 3，交互又以浏览为主。二值化把浏览与购买视为同强度，共现也可能代表共同浏览或商品替代，因而覆盖更广却可能难以预测未来购买。低频组下降最大，但有效分母只有 53，这些解释是待验证假设。样本只有一个站点和两个月的观察期，缺少真实库存、曝光、上线流量与统计显著性证据。本轮只验证离线和既有后端契约回归，未验证线上推荐服务。

后续如获审查批准，可以在同一验证窗口比较行为权重、受控的购买热门混合和相似度收缩，再决定是否进入下一模型。使用既有测试结果作最终对照，避免测试集参与调参。
