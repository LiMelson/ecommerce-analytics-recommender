# P0-REC-01 交接数据验收

样本通过本阶段离线 Benchmark 的文件完整性及内容验收。Arrow 的时间列缺少时区标记，已按核实的 UTC 清洗规则处理。原始月文件及实际送交网站的独立 CSV 未随交接包提供。各项计数和环境见 [数据验收 JSON](../recommendation/reports/p0-rec-01-audit.json)。

## 文件与事件

- 对 `data/processed/events_sample.parquet` 独立计算 SHA-256，结果为 `7f6fe3cf0dee62e04665b09e921be290e127f947e4f6baf97837549cc42cf771`，与交接清单一致。读取物理字段后，再生成 UTC 时间列供训练；读取过程没有删除或填充行为事件。
- 1,079,354 条行为、52,687 名用户、81,693 件商品。浏览 1,024,977 条、加购 37,698 条、购买 16,679 条，收藏和移出购物车均为 0。原始行为映射不一致为 0，十列完全重复的多余行数为 0。粒度为行为事件，缺少事件 ID，无法判断源清洗时合并了多少同秒且字段相同的真实行为。
- 八个文本字段物理类型均为 Arrow `string`，包含 `user_id`、`item_id`、`category_id`、`category_code`、`brand`、`behavior_type`、`raw_event_type`、`session_id`。用户和商品 ID 保留为字符串，必填字段无空值。价格为 `double`，空值和负数为 0，零价 2,508 条，会话缺失为 0。品牌缺失 151,135 条（14.00%），类目编码缺失 348,267 条（32.27%），类目 ID 空值和 `unknown` 均为 0。品牌、价格及会话仍保留在训练文件中。
- `event_time` 文件类型为 `timestamp[us]`。DuckDB 源码用带字面量 `UTC` 的格式解析源字符串，写出时没有时区元数据。读入对时钟值附加 UTC，无需平移钟点。实测范围为 2019-10-01 00:08:55 至 2019-11-30 23:59:58 UTC。后续数据交付宜在 Parquet 写出 UTC 元数据，减少不同读取端的解释差异。
- 所有 52,687 个用户字符串均可转 `BIGINT`，并通过源码的数字条件 `user_id % 1000 < 10`。代码在用户 ID 上选择并保留合格事件，再做整行去重。`seed=20261116` 只出现在非数字 ID 的哈希分支，本样本有 0 个非数字用户，换成 `20261117` 时样本里的非数字命中仍为 0，所有实际用户走与 seed 无关的分支。取模抽样可能受 ID 分配规律影响。完整历史的范围是两个月源文件内通过有效性过滤与去重的事件。缺少原始文件，无法逐用户验证历史有无遗漏、全体抽样率或总体代表性。

## 网站五列文件对应关系

用 PR #2 原有导出器从交接 Parquet 在临时目录重新生成五列 CSV。导出 1,079,354 行，排除事件 0 条。`user_id,item_id,category_id,behavior_type` 直接映射，未知类目映射为空，`event_time` 写为 UTC Unix 毫秒 `timestamp`。时间戳范围为 1569888535000 至 1575158398000。五列组合有 114 条重复余行，可能来自可区分的训练扩展字段被投影掉。现有导出与后端入库契约保留这些事件，避免凭五列再去重造成额外损失。

实际再生 CSV SHA-256 为 `ec64ad5f5c7157d2425710232f550872044d871f88050b211c46ad97869513bc`，与交接记录声明的网站 CSV 完全一致。CSV 在检测结束后从临时目录清理。后续对接时，仍须核对实际导入文件校验和及后端生成的正式 dataset_id。离线实验使用由样本哈希派生的本地 ID。
