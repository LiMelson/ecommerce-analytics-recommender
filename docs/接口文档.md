# 接口文档 · v0.2

更新日期：2026-11-16。当前实现：FastAPI + MySQL + ClickHouse，统一前缀 `/api/v1`。

运行服务后访问 <http://127.0.0.1:8000/api/docs> 查看可交互文档；[OpenAPI JSON](openapi.json) 包含请求与主要响应字段，可导入 Apifox、Postman 等工具。路径、类型以当前 OpenAPI 和源码为准，早期需求文档中的演示接口由本文件取代。

## 公共约定

- 系统账号用于登录；行为中的 `user_id` 是匿名数据标识，二者不混用。
- 用户、商品、类目及数据版本 ID 使用字符串，保留前导零。
- 行为 `t`、数据起止时间使用 Unix 毫秒；账号、日志、任务的 `created_at`、`updated_at` 使用 Unix 秒。日期筛选及图表按北京时间；导入的 ISO 时间必须带时区。
- 分页通常使用 `page`（从 1 开始，最多 10000）、`page_size`（1–100，默认 20）；返回 `items,total,page,page_size`。亿级明细应按用户/商品或日期缩小范围，不通过无限翻页取训练数据。
- 统计、画像、行为查询可传 `dataset_id`，省略则在请求开始时选定活动版本。响应包含实际版本；前端联调时应显式传入页面已选择的版本。
- 同一数据版本发布后不修改行为记录；重新导入产生新版本。
- 当前没有公开注册。管理员创建账号、指定角色和初始密码。密码长度为 10–128 字符，使用 Argon2 哈希保存。

## 登录与请求头

```http
POST /api/v1/auth/login
Content-Type: application/json

{
  "username": "admin",
  "password": "<填写本机首次管理员文件中的密码>"
}
```

成功返回 `account`、`permissions`、`csrf_token`，同时通过 `Set-Cookie` 设置 `commerce_session`（HttpOnly、SameSite=Lax）。前端与后端通过 Vite `/api` 代理保持同源；正式 HTTPS 部署须将 `COOKIE_SECURE=true`。

后续 GET 请求由浏览器自动带 Cookie。POST、PATCH 等写操作还需加：

```http
X-CSRF-Token: <本次登录返回的 csrf_token>
```

刷新页面后通过 `GET /auth/me` 恢复当前账号及 CSRF Token。此实现使用 Cookie 会话，不使用 Bearer JWT；不要在浏览器 localStorage 保存登录凭据。非浏览器客户端需自行保留 Cookie 并设置 CSRF 请求头。

统一错误示例：

```json
{
  "error": {
    "code": 403,
    "message": "当前账号没有此操作权限",
    "details": null
  },
  "request_id": "请求编号"
}
```

主要状态码：401 未登录/会话失效，403 权限或 CSRF 失败，404 不存在，409 状态冲突，413 上传过大，422 参数不符，429 登录频率限制，502 算法服务返回不符，503 数据库或算法服务不可用。

## 账号、个人资料与角色

| 方法与路径 | 输入 | 权限/结果 |
|---|---|---|
| `POST /auth/login` | `username,password` | 登录；同一来源五分钟最多十次尝试 |
| `GET /auth/me` | 无 | 当前账号、角色、权限、CSRF Token |
| `POST /auth/logout` | 无 | 删除当前会话 |
| `PATCH /auth/me` | `name,email,team,note` | 更新自己的资料 |
| `POST /auth/password` | `current_password,password` | 修改自己的密码，全部会话失效 |
| `GET /accounts` | 分页 | 账号管理权限；不返回密码哈希 |
| `POST /accounts` | `username,name,password,role_id,enabled` | 创建账号；账号重复返回 409 |
| `PATCH /accounts/{username}` | `name,role_id,enabled` | 修改账号；角色或启停改变会撤销全部会话 |
| `POST /accounts/{username}/password` | `password` | 管理员重置密码并撤销会话 |
| `GET /roles` | 无 | 登录后可查看角色和权限列表 |
| `PATCH /roles/{role_id}` | `permissions` 字符串数组 | 账号管理权限；即时生效 |

`role_id` 固定为 `admin/analyst/viewer`。账号格式：小写字母开头，3–30 位小写字母、数字、下划线或短横线。管理员不能停用自己或修改自己的角色；系统保护最后一个启用的管理员。管理员角色保留全部权限，其他角色不能获得账号管理权限，所有角色至少保留数据概览。

## 数据集与后台任务

| 方法与路径 | 输入 | 说明 |
|---|---|---|
| `GET /datasets` | 分页 | 元数据、导入状态、SHA-256 和是否活动 |
| `GET /datasets/active` | 无 | `dataset`，尚未导入时为 null |
| `GET /datasets/template` | 无 | 下载标准 CSV；需要数据导入权限 |
| `GET /datasets/inbox` | 无 | 管理员查看服务器收件目录前 200 个文件名和大小 |
| `POST /datasets/import` | multipart 字段 `file`；可选 query `name,activate` | 网页上传，默认上限 100 MB，返回 202 |
| `POST /datasets/import-local` | `relative_path,name,activate` | 管理员提交服务器文件，支持大文件 |
| `POST /datasets/{id}/activate` | 无 | 切换已完成版本；数据导入权限 |
| `GET /jobs` | 分页 | 管理员查看全部任务，导入人员只看自己的 |
| `GET /jobs/{id}` | 无 | 状态、已处理行数和失败原因 |
| `GET /jobs/{id}/download` | 无 | 下载已完成的导出文件，检查任务归属 |
| `POST /jobs/{id}/recover` | 无 | 管理员结束超过十分钟无心跳的任务 |

导入响应形状：

```json
{
  "dataset": { "id": "数据版本", "status": "queued", "其他字段": "见 OpenAPI" },
  "job": { "id": "任务编号", "kind": "import", "status": "queued", "其他字段": "见 OpenAPI" }
}
```

服务端文件导入例：

```json
{
  "relative_path": "cleaned-events.parquet",
  "name": "电商行为数据第一版",
  "activate": true
}
```

文件必须已放在 **后端进程所在机器** 的 `backend/instance/inbox/` 中；支持该目录内的相对路径，拒绝越界和指向外部的符号链接。不会根据请求下载外部 URL，也不接受任意绝对路径。

任务由独立 `app.worker` 执行。状态为 `queued → running → ready/failed`；数据集对应 `queued → importing → ready/failed`。先写入 ClickHouse 并生成汇总，再通过 MySQL 事务发布成功版本。任何行校验失败都不发布整个版本，原活动版本继续可用。重复事件原样保留，不跳过坏行、不做数据清洗。

`activate=true` 只在活动版本仍等于提交时的版本时自动切换，避免较早排队的任务覆盖其他人刚选择的版本；其他情况导入完成后手动切换。任务进程中断后不在原版本上盲目重试，管理员结束过期任务后重新导入新版本。失败版本的物理数据暂留 ClickHouse，尚无自动清理策略。

## 统计、画像与行为明细

| 方法与路径 | 输入 | 结果 |
|---|---|---|
| `GET /overview` | 可选 `dataset_id` | `counts,total,users,items,categories,days` |
| `GET /analytics/daily` | 可选版本 | 日期、pv/fav/cart/buy、日去重用户数 |
| `GET /analytics/hourly` | 可选版本 | 北京时间 0–23 点行为次数 |
| `GET /analytics/funnel` | 可选版本 | 同用户、同商品严格递增时间路径的数量 |
| `GET /analytics/rf` | 可选版本 | RF 分群及人数，金额 M 缺失 |
| `GET /analytics/retention` | 可选版本 | 样本首现分组，当日及后七天留存；未覆盖为 null |
| `GET /analytics/category`、`/product` | 可选版本 | 购买事件排行，最多 100 项，前端展示前 20 |
| `GET /users` | 分页、用户前缀 `keyword`、`segment`、版本 | 匿名用户汇总，用于选择和分群表 |
| `GET /users/{id}/profile` | 可选版本 | 行为分布、RF、前 20 类事件次数、最近 20 条记录 |
| `GET /behaviors` | 分页、`keyword,behavior,from_day,to_day,dataset_id` | 明细页；keyword 精确匹配用户或商品 ID |
| `POST /behaviors/export` | 与明细相同的筛选，不传分页 | 创建导出任务，最多 100 万条 |

明细按日期、用户 ID、时间、序号倒序，和 ClickHouse 排序键对应；**并非跨全部用户的单纯时间倒序**。前端默认筛选最近七天；概览与统计使用整个所选数据版本。日期边界包含首尾两日。

明细记录使用前端已有的字段名：

```json
{
  "id": 1,
  "user": "u001",
  "item": "p001",
  "category": "c001",
  "type": "buy",
  "t": 1793462400000
}
```

RF：R 为距版本最后一条记录的购买间隔天数；无购买时为 null。F 为购买事件次数。R≤2 视为近期、F≥12 视为高频。画像类目分布仅按事件次数统计，不使用训练算法或行为权重。漏斗同一时刻发生的不同动作不作为严格先后关系；首页漏斗仅比较事件总数。

导出 CSV 对 `= + - @` 开头的标识增加前置单引号，减少表格公式执行风险。这种面向表格查看的导出不作为训练原始数据，训练请使用数据组保存的 Parquet 和固定划分。

|---|---|---|

## 算法组接入

| 方法与路径 | 输入 | 结果 |
|---|---|---|
| `GET /models/active` | 无 | not_connected / registered / incompatible 及模型元数据 |
| `POST /models` | `id,dataset_id,name,metrics,note` | 管理员登记模型，不执行训练、不读取权重文件 |
| `POST /models/{id}/activate` | 无 | 只允许启用与活动数据版本一致的模型 |
| `GET /recommendations` | 仅 `user_id` | 服务端固定配置调用算法组服务，最多 Top10 |

详细协议见 [数据与算法交付约定](数据与算法交付约定.md)。算法服务未配置或模型未登记时返回 503；切换数据后模型不兼容返回 409；上游超时、版本或格式不符返回 502。没有真实训练接口，也不提供前端超参数选择。

## 运行状态与部署边界

`GET /api/health` 检查两种数据库，全部可用返回 200/ready，否则 503/degraded。它不代表 worker 正在消费任务，也不代表算法服务已接入。

当前默认绑定本机回环地址，单个 API 进程、一个任务 worker；登录频率限制保存在 API 进程内。若部署多 API 实例，应先增加共享限流、反向代理上传大小和速率限制、HTTPS、备份以及服务监控。当前没有自动发布到公网。
