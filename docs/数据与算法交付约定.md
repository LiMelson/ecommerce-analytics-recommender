# 数据与算法交付约定

更新日期：2026-11-16。数据清洗、训练、调参与模型选择由数据和算法负责人实现。后端已经提供数据版本管理、入库、统计与推荐服务适配入口，不执行这些算法工作。

## 数据组交付

保留原始数据和完整训练特征文件，另输出一个供网站入库的标准 CSV/Parquet：

| 字段 | 类型与要求 |
|---|---|
| `user_id` | 字符串或整数，入库作为字符串保存，最长 128；不能为空、含控制字符或首尾空白 |
| `item_id` | 同上 |
| `category_id` | 可选；未知时留空，不编造类目 |
| `behavior_type` | 仅 `pv/fav/cart/buy`，分别表示浏览、收藏、加购、购买 |
| `timestamp` | 10 位秒、13 位毫秒，或带时区 ISO 时间；范围 2000–2100 |

文件必须带唯一表头，UTF-8 CSV 可有 BOM。网站入库文件不接受额外列；会话、品牌、价格、训练特征等仍保留在算法使用的完整文件中，避免丢失训练信息。Parquet 中的 ID 同样应为字符串或整数，timestamp 建议使用 int64 毫秒。

后端不将 `view` 自动猜成 `pv`，不将移出购物车当作收藏，不自动跳过坏行或去重。字段适配与事件语义由数据组先确认。导入保留重复事件；若业务上确认应去重，由数据组在清洗阶段处理并记录规则。

网页支持至多 100 MB 文件；大文件放入运行后端的机器的 `backend/instance/inbox/`，由管理员在“数据管理 → 后台任务 → 导入服务器文件”提交，或使用：

```sh
cd backend
python -m app.cli import-file cleaned-events.parquet --name 数据集第一版
```

该命令只是入队，需要同时运行 `python -m app.worker`。命令行输出数据版本 ID 和任务 ID。网站统计直接使用入库结果；训练文件另行分批读取，不从网页下载亿级记录。

随数据提供：来源链接与许可说明、原始范围与实际采用的样本范围、字段映射、时间与时区、事件分布、缺失/重复处理报告及文件校验信息。不要把数据集提交到 GitHub。

## 算法组交付

1. 固定训练、验证和测试时间划分，明确目标为购买或其他交互，避免未来信息泄漏。
2. 保存模型、用户和商品 ID 映射、训练数据版本、参数配置、随机种子及真实评估结果。
3. 提供一个独立 Python 推理服务，开发团队固定算法和参数；后端不会把学习率、维度或迭代次数交给网站操作人员。
4. 在后端本地 `.env` 中设置 `RECOMMENDER_URL` 为推理接口的完整 URL，例如 `http://127.0.0.1:9001/predict`。这个地址由服务配置固定，不从网页请求接收。
5. 管理员使用 `/models` 登记模型版本，再使用 `/models/{id}/activate` 启用。登记数据版本须与当前入库版本对应。

后端向推理服务发出的 JSON：

```json
{
  "user_id": "匿名用户ID",
  "dataset_id": "已完成入库的数据版本ID",
  "model_version": "bpr_v1",
  "limit": 10
}
```

推理服务须返回：

```json
{
  "user_id": "匿名用户ID",
  "dataset_id": "已完成入库的数据版本ID",
  "model_version": "bpr_v1",
  "items": [
    {
      "item_id": "商品ID",
      "category_id": "类目ID或空字符串",
      "rank": 1,
      "score": 2.31,
      "reason": "可依据模型和真实特征解释的说明"
    }
  ]
}
```

- 三个标识必须与请求一致，商品 ID 不重复，rank 从 1 连续递增，最多 10 项；允许没有可推荐商品时返回空数组。
- `score` 可为 null；有分数时必须是有限数值。前端显示原始模型分数，不自动解释为购买概率或百分比。
- 不知道类目时返回空字符串，不编造商品名称、图片或推荐原因。
- 已购买商品过滤、候选集、冷启动和热门兜底由算法组按固定配置实现，写入算法说明。
- 后端设置五秒上游超时，验证响应不超过 1 MiB；开发时先预加载模型和 ID 映射，不在每次推荐请求中重新训练。
- 服务不会反序列化从网页上传的 pickle 或执行算法组提交的任意脚本。算法服务独立运行，通过 HTTP 协议接入。

## 版本对齐

网站数据版本是导入生成的不可变 ID，模型登记使用该 ID。算法组应说明其原始文件与网站数据的对应关系及文件 SHA-256；不能仅凭同名文件认定训练和网站使用的是同一批数据。切换数据版本后，旧模型仍保留登记记录，推荐接口会拒绝不兼容版本。
