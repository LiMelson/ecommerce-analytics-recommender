## 1. 项目与职责

系统从历史电商行为生成可解释的商品 Top10。张凯博负责推荐样本适配和验收、统一评估、Popular、ItemCF 和 BPR-MF 的实现与实验、改进研究、模型资产、推理接口和算法侧交接。独立 HTTP 服务供团队调用。网站页面、业务 API、数据库和部署联调由其他组员负责。阶段成果与本轮操作步骤见[最终交接](P0-REC-06-算法模块最终交接.md)。

本轮保留原算法、训练参数、评估协议和冻结报告。正式资产沿用经核验的 04A 发布文件。结论适用于受控样本和独立推理；网站发布以完成真实入库数据版本绑定及集成验收为前提。

## 3. 时间切分、候选与指标

协议 `purchase_global_utc_v1` 用经过时间的 70% 和 85% 切分，三个区间左闭右开。验证模型拟合只用训练窗口；正式测试在选定参数后使用训练加验证拟合。本地发布模型固定在后者的快照，共 929,827 条事件。样本身份、UTC 拟合边界与训练内容 SHA-256 `95a6fc7a551b2385beac77fa09783ed45d2de9dd7b003e7a725db0f6e6ab1f02` 共同标识资产。 [Benchmark 协议](P0-REC-01-Benchmark.md) · [训练快照代码](../recommendation/training_snapshot.py)

| 窗口 | UTC 起点（含） | UTC 终点（不含） | 事件 | 窗口用户 |
| --- | --- | --- | ---: | ---: |
| 训练 | 10-01 00:00 | 11-12 16:48 | 627,023 | 39,236 |
| 验证 | 11-12 16:48 | 11-21 20:24 | 302,804 | 18,438 |

时间均为 2019 年。目录只含截止点前出现过的商品，包含此前仅被浏览或加购的商品。每个用户过滤自己的历史已购，去重未来购买标签，将截止后首现商品与历史复购排除主标签。评估器遍历窗口内出现的所有用户，主分母只计至少一个可达购买目标的用户。测试 1,798 个去重购买对中，1,561 可达、173 历史复购、64 未来商品。测试 1,250 名购买者中，128 名全部目标不可达。附加全购买目标口径保留这些不可达目标。评估使用全目录规则；BPR 的负采样仅用于训练。 [冻结三模型结果](P0-REC-03-BPR实验与复现.md)

令 K=10，T 为去重目标集合，H 为前 K 条与 T 的交集。Recall 为 |H|/|T|，Precision 为 |H|/K，HR 为有命中取 1、否则取 0。DCG 为 Σᵣ relᵣ/log₂(r+1)，IDCG 将 min(K, |T|) 个命中排在最前，NDCG 为两者之比。四项对有效用户做等权宏平均。目录覆盖为用户范围内收到的不同商品数除以截止前目录大小；测试目录 75,327，验证目录 60,817。候选不足仍用固定 Precision 分母 K。 [指标实现](../recommendation/benchmark.py)

活跃度阈值来自初始训练期事件数的 nearest-rank P25=2、P75=15。冷、低、中、高分组分别为 0、1–2、3–15、至少 16 条；阈值保持固定，用户历史按各窗口自己的截止点计算。与冷启动不同，浏览或加购但未购买的用户有真实历史，ItemCF 可用其交互，购买版 BPR 使用热门兜底。 [Benchmark 协议](P0-REC-01-Benchmark.md)

## 4. 三个模型及实现

| 模型 | 拟合方式 | 推理与稳定性 |
| --- | --- | --- |
| Popular v1 | 截止前每件商品的 buy 事件数，零次购买商品仍在榜单中 | 降序按次数，同分按字符串商品 ID；过滤已购。类目取截止前最近已知值，同一时刻按类目 ID 升序 |
| ItemCF v1 | pv/cart/buy 转为二值交互；每人按时间保留最近 100 件，商品保留最多 80 个正相似非自身邻居 | 将用户种子商品的邻居相似度按候选求和，过滤已购，按分数降序和 ID 升序。相似候选不足时在尾部按热门补位，缺候选或无历史时走热门 |
| BPR-MF | 去重训练购买对，负例在该用户训练已购的补集中均匀抽样。16 维、40 Epoch、seed 20261120、每正例 3 个负例、学习率 .05、正则 .01、batch 128 | 对有购买正信号的商品计算向量内积并过滤已购，稳定按 ID 解同分。无购买、无可用向量等走明确的热门分支，候选少时补位 |

Popular 见 [popular.py](../recommendation/popular.py)。ItemCF 对二值列 xᵢ、xⱼ 计算 xᵢ·xⱼ/(‖xᵢ‖‖xⱼ‖)，等价于共同交互用户数除以两商品各自交互用户数乘积的平方根。训练对 CSR 分 256 行做乘法，仅保留 Top80 邻居。 [ItemCF 实现](../recommendation/itemcf.py)

BPR 根据 Δ=pᵤ·(qᵢ−qⱼ) 最小化单三元组损失 log(1+exp(−Δ))+λ(‖pᵤ‖²+‖qᵢ‖²+‖qⱼ‖²)/2。固定种子控制初始化、洗牌与训练负采样，`logaddexp` 和 `expit` 负责稳定计算，`np.add.at` 累积同批重复索引的更新。冻结测试拟合的固定训练诊断损失约从 0.69553 降到 0.08455，衡量的是训练三元组拟合。 [BPR 实现](../recommendation/bpr.py) · [实验记录](P0-REC-03-BPR实验与复现.md)

全新用户三模型共用同一训练期热门榜。个性化与补位由模型决定，统一引擎依其原顺序生成 rank，并核查目录、已购、重复、数量及有限分数。模型状态使用冻结数据类、只读映射、元组、不可变集合与字节缓冲区；`describe` 回传元数据副本。独立服务在开始收请求前预加载，推理路径复用模型，跨用户连续调用和并发均通过对照。 [统一引擎](../recommendation/engine.py) · [服务实现](../recommendation/http_service.py)

## 7. 模型资产、接口和工程验收

- 资产为 ZIP 容器内的 JSON 和安全数值数组，`allow_pickle=False`。Popular 保存热度、目录、类目、历史统计与已购；ItemCF 另含 CSR 和 ID 映射；BPR 另含映射和因子。个性化资产均自带同快照热门后备。保存使用同目录临时文件、完整试加载及原子替换，最后发布注册表。注册表整文件哈希、成员哈希、格式、数据版本、模型版本和源码身份交叉核对。加载无需样本或训练。
- Python 支持单用户和按输入顺序批量预测。独立 HTTP 提供 `POST /predict`、`GET /health`、`GET /ready`。请求只能选择已登记模型版本和匹配的数据版本，模型文件由操作员配置。响应含 item_id、category_id、rank、score、reason，按 rank 展示。三个分数尺度不同，且均无购买概率含义。
- 续接时已有两处实质性加固。此前在同一个引擎中，两件各自合法但训练快照不同的资产可使用同一 dataset_id。现在 `RecommendationEngine._install` 比对协议、拟合起点、截止点和快照内容哈希，在安装第二个冲突资产前返回 `model_identity_mismatch`。正式资产快照一致，原排序保持不变。离线验收工具原依赖 assert；现在 `verify_real` 和 `verify_http` 在 Python 优化模式下明确失败，防止跳过断言后留下误导性通过结果。合成回归覆盖内存模型、预加载、延迟加载和两个验收入口。 [引擎](../recommendation/engine.py) · [回归测试](../recommendation/tests/test_delivery.py)
- 推荐与数据测试分别为 130、33 项通过，失败和跳过均为 0。推荐 Ruff lint 和 26 个文件的格式检查通过。团队数据目录应用同一 Ruff 配置仍有既有 lint 和格式问题，属于数据组维护项。两套 pytest 若放在同一个进程中，数据目录配置会令 `data_algo` 导入名冲突，应按交接命令分开执行。推荐测试出现一条已有 Starlette TestClient 对 HTTPX 的弃用警告。 [运行入口](P0-REC-06-算法模块最终交接.md)
- 本轮重新审计真实 Parquet，重放验证集消融，核验正式资产。每模型 15,158 个冻结请求的有序商品与来源指纹均匹配。真实 TCP 的 1,320 个计时请求逐字段匹配 Python，另有真实错误码验证。两个不同 PID 的服务依次启动，18 个并发请求结果与 Python 单用户及批量参考一致。恢复的 P0-REC-06 记录还保存了固定配置、单独目录构建和加载前后实际对照；本次发出的资产仍选用原 04A 发布品。审查包附聚合证据。

## 9. 保留方案、研究局限与集成条件

保留三个正式模型和原版 ItemCF。当前样本以购买排序为主要目标时优先以 Popular 作为基线，ItemCF 提供个性化和更广目录覆盖，BPR 保留为购买偏好建模对照。离线宏平均适用于这份抽样、这两个窗口及可达目标；网站转化、库存约束、复购政策和长期效果需要独立证据。本轮可确认的工程成果包括三模型、统一 Benchmark、受控资产、Python/HTTP 接口、冻结排序回归和研究代码隔离。

交接条件是由团队通过受控渠道接收模型；用实际入库版本、校验和、ID、目录及训练窗口确认兼容后，再生成或登记绑定正式网站 dataset_id 的资产。保留校验，并以真实调用方开展契约、鉴权和部署容量验收。当前可独立用于本地推理与代码审查，正式网站接入仍有这些前置条件。 [交接步骤](P0-REC-06-算法模块最终交接.md)
